# Конфігурація ПК-прототипу

`config::HostConfigStore::load(input, origin)` читає текстовий файл з парами `key=value`. Порожні рядки й рядки, що починаються з `#`, ігноруються. Усі шість полів обов'язкові; повтори й невідомі поля відхиляються. Після повної перевірки сховище публікує незмінний `ConfigSnapshot` з версією та `origin`. Помилка повертає категорію і назву поля та залишає попередній знімок активним.

| Поле | Значення | Одиниця / правило |
| --- | --- | --- |
| `source` | `controller_telemetry`, `direct_gnss`, `ground_station`, `simulation` | Логічне джерело стану |
| `reading_type` | `position_estimate`, `gnss_fix`, `simulated_sample` | Зміст зразка, а не формат пакета |
| `max_measurement_age_us` | Додатне ціле | Максимальний вік вимірювання, мкс |
| `max_delivery_delay_us` | Додатне ціле | Максимальна затримка доставки, мкс; не більше віку |
| `max_horizontal_accuracy_m` | Невід'ємне скінченне число або `none` | Межа метричної горизонтальної похибки, м |
| `minimum_gps_fix` | `2d`, `3d` або `none` | Мінімальний GPS fix |

Приклад для демонстрації GNSS на ПК:

```text
source=direct_gnss
reading_type=gnss_fix
max_measurement_age_us=200000
max_delivery_delay_us=50000
max_horizontal_accuracy_m=5
minimum_gps_fix=2d
```

Числові межі тут лише демонстраційні. Для реального БПЛА їх треба обрати за властивостями датчика, каналу доставки й вимогами до контуру керування.

`simulation` вимагає `simulated_sample`; `direct_gnss` вимагає `gnss_fix`; `gnss_fix` вимагає мінімальний fix. `position_estimate` не допускає межу метричної точності або fix, оскільки поточний провайдер оціненої позиції таких показників не надає. Поля `none` явно вимикають відповідні перевірки. Значення `ground_station` описує можливе джерело в ПК-сценарії; воно не означає потреби в постійному зв'язку під час автономного польоту.

Сховище не відкриває файли самостійно: інтеграція передає `std::istream` і ідентифікатор `origin`. Це API для ПК, без визначення wire-формату сенсора, MAVLink-налаштувань, постійного зберігання або правил зміни конфігурації під час місії. Порогові поля знімка передаються у `StateValidator`; інші модулі отримують той самий `shared_ptr<const ConfigSnapshot>` і можуть перевірити його версію.
