# Перевірка зразка стану

`StateProvider::take_latest()` повертає кандидат `StateSample`. Перед навігаційним розрахунком його слід передати до `StateValidator::validate(sample, now)`. Результат містить прийнятий зразок або конкретну причину відхилення; відхилений зразок не змінює останній прийнятий час.

`StateValidationConfig` задається інтеграцією або тестовим сценарієм. Він містить `max_measurement_age_us`, `max_delivery_delay_us`, необов'язкові `max_horizontal_accuracy` у метрах і `minimum_gps_fix` (2D або 3D). Відсутній поріг точності дозволяє зразки без метричної точності; відсутня мінімальна вимога fix дозволяє зразки без даних про fix, але явний `no_fix` завжди відхиляється. Конфігурація з від'ємною/нескінченною межею точності або некоректним мінімальним fix відхиляється.

Перевірка часу вимагає `measured_at ≤ received_at ≤ now`, `now − measured_at ≤ max_measurement_age_us` і `received_at − measured_at ≤ max_delivery_delay_us`. Моменти вимірювання мають строго зростати окремо для кожного джерела; час прийому не може зменшуватися. Усі три моменти мають бути вже виражені монотонним годинником модуля. Валідатор не виводить цей час із MAVLink `time_boot_ms` або `time_usec`.

У [тестовому сценарії](../tests/python/test_state.py) для перевірки меж явно задано 200 мс максимального віку, 50 мс затримки доставки, 5 м горизонтальної точності та мінімум 2D fix. Це демонстраційні значення, а не вимоги до реального БПЛА. Валідація перевіряє скінченність і діапазони значень у вже нормалізованих одиницях; вона не може визначити, чи зовнішній відправник помилково назвав радіани градусами. Таке зіставлення належить адаптеру протоколу.
