# KPI4 — модуль корекції траєкторії БПЛА

Курсовий проєкт присвячений бортовому модулю, який веде автономний БПЛА за маршрутом і коригує відхилення. Ground Station перед польотом завантажує місію через MAVLink. Під час польоту модуль отримує актуальний стан із бортового джерела, зокрема GPS, обчислює нову ціль руху й передає її контролеру X. Контролер відповідає за стабілізацію та мотори. Постійне з'єднання з Ground Station для контуру корекції не потрібне.

Працює замкнена ПК-демонстрація: ядро рахує відхилення від маршруту та формує горизонтальну швидкість до точки попереду. Стенд проходить кілька waypoint, перевіряє шум GPS і призупиняє видачу команд за непридатного або відсутнього стану:

```sh
cmake -S . -B build
cmake --build build
./build/kpi4_demo --scenario route --noise 0.35 --fault stale --output build/route
ctest --test-dir build --output-on-failure
```

Маршрут містить три відрізки та два повороти. Навіть із двосекундною перервою в придатних вимірюваннях модель завершує місію після відновлення даних; причина відмови та відсутність нових команд видимі в CSV. [Параметри й поведінка стенда](docs/route-demo.md), [результати D2](devlogs/manual/D2-route-demo/README.md).

Команда `./build/kpi4_demo --output build/demo` зберігає попереднє порівняння на одному відрізку: максимальне відхилення 2,06 м із корекцією проти 25,05 м без неї. [Алгоритм і модель](docs/guidance-demo.md), [прогін D1](devlogs/manual/D1-guidance-demo/README.md). Обидва сценарії — умовний горизонтальний стенд із внутрішньою місією. Конкретна MAVLink-команда виходу, джерело бортового стану й апаратна платформа ще не вибрані.

ПК-читалка MAVLink перевіряє кадри, CRC та незалежні логічні канали. Протокольна бібліотека декодує `HEARTBEAT` і повідомлення місійного обміну, нормалізує глобальні цілі у WGS84 з явним altitude reference та наразі приймає в місії лише `MAV_CMD_NAV_WAYPOINT`; [ручний прогін M01](devlogs/manual/M01-frame-reader/README.md) зберігає команди й результати фреймінгу. Протокольні компоненти й демонстрація корекції поки запускаються окремо.

Вимоги до інструментів ПК-розробки: [docs/build.md](docs/build.md).

Декодери `GLOBAL_POSITION_INT` і `GPS_RAW_INT` передають оцінений стан та сирі GNSS-дані до спільного `StateProvider`/`StateSample`. Симулятор використовує такий самий інтерфейс. Інтеграція явно задає монотонні моменти вимірювання й прийому. Python-тести порівнюють еквівалентні дані з MAVLink і симулятора.
Перед використанням у навігації зразок перевіряє `StateValidator`; часові й GPS-пороги надходять із конфігурації. Приклад та правила відхилення наведено в [docs/state-validation.md](docs/state-validation.md). Формат файла налаштувань для ПК і API атомарного знімка описані в [docs/configuration.md](docs/configuration.md).

`MissionUploadAssembler` збирає місійні елементи в порядку та видає кандидат-план тільки після повного upload. `MissionPlanStore` зберігає прийняту незмінну версію, блокує конфлікт джерел до старту й фіксує власника після нього. Логічні запити елементів, підтвердження та правила сховища описані в [docs/mission-upload.md](docs/mission-upload.md).
